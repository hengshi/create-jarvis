# Instance Readiness

Use this checklist to judge whether a generated JARVIS is only installed, pilot-ready, pilot-proven, operational, or mature.

## Level 0 - Installed Scaffold

An installed scaffold exists when:
- root structure exists;
- maintenance guidance exists;
- some templates or inventories exist;
- and the runtime can link the entry skill if runtime-driven.

An installed scaffold is not yet operational.

## Level 1 - Pilot-Ready

A pilot-ready instance exists when:
- one real business loop is defined;
- key sources, repos, and workflows for that loop are inventoried;
- at least some source / repo / workflow skills are drafted;
- truth-bearing fields are confirmed or explicitly unresolved;
- owners and escalation paths are known;
- and another agent or owner can start the pilot without starting from zero.

Pilot-ready means ready to run. It does not prove the method worked yet.

## Level 2 - Pilot-Proven

A pilot-proven instance exists when:
- at least one real START -> WORK -> END loop has been run;
- evidence shows where JARVIS helped and where it failed;
- failures have been classified;
- skill backlog changes include `no_skill_gap`, merge, update, or create decisions;
- controlled writeback has been proposed or completed with owner review.

Pilot-proven proves direction, not completeness.

## Level 3 - Controlled Operations

An operational instance exists when:
- modules contain real knowledge, not placeholders;
- source routing is real and usable;
- repo-local truth is linked correctly;
- workflow closure is explicit;
- START -> WORK -> END writeback is happening in practice;
- and calibration is preventing skill bloat.

At this level, JARVIS can already reduce rediscovery and handoff cost in day-to-day work.

## Level 4 - Mature Instance

A mature instance exists when:
- historical knowledge is deep and structured;
- repeated failures are captured as patterns;
- decisions and rejected ideas are recorded with rationale;
- cross-cutting knowledge is actively maintained;
- ownership is stable;
- eval cases and calibration loops run regularly;
- and the system keeps improving from actual use.

At this level, JARVIS is no longer just a repository. It is part of how the organization thinks and works.

## Readiness Checks

Before calling an instance operational or mature, confirm:
- [ ] business modules have real overview / issue / decision content
- [ ] sources have real routing docs
- [ ] cross-cutting knowledge exists where needed
- [ ] company-specific JARVIS skill entry exists
- [ ] repo skills and workflow skills exist where the main loops require them
- [ ] writeback happens after real work, not only during setup
- [ ] pilot evidence exists before pilot success is claimed
- [ ] calibration decisions include `no_skill_gap` when appropriate
- [ ] another owner or agent can continue without rediscovering fundamentals
