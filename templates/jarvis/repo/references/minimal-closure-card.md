# 最小闭合卡

工作流结束、交付或写入决策前使用。卡片应人类可读、按任务实际情况适配，而非套用固定 schema。

## 必需语义

每张闭合卡必须让后续读者直接判断任务停在哪里：

- **结论**：本次任务的最终结果（完成 / 阻断 / 重定向）。
- **原始目标指向**：指向原始 goal、artifact 或问题描述的引用，使闭合卡与任务可联动追溯。
- **实际完成的工作**：实际做了什么的简要描述。与原始 scope 的差异需注明。
- **验证状态与证据**：关键 claim 的验证结果和证据索引。如验证未执行，说明原因和归属。
- **未解决项与风险**：已知未闭合的开放问题、已知风险或已知局限性。
- **后续动作**：结果不是 completed 或仍有 handoff 时，记录下一步及其 authority。

## 补充语义

以下内容按实际情况决定是否出现：

- `no_skill_gap`：仅当任务过程中确实执行了 skill-gap 判断时才记录。普通任务省略此字段。
- **写入决策**：仅当存在 self-improvement signal 时记录。
- **Task identity**：仅当当前执行来自真实 jarvis-box managed Task 时记录。
- 中间产物、替代方案和 gate evidence：只有它们影响结果或 handoff 时记录。

## 规则

1. 结论、原始目标、实际工作、验证状态或 material unresolved 缺失时，仍是草稿。
2. 验证未执行时，说明原因和归属。
3. 不做无依据的写入决策。无信号就沉默。
4. 不人为制造字段填充任务。
