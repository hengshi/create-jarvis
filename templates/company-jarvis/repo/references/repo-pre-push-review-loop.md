# 仓库推送前审查循环

## 适用条件

仅当当前仓库、客户或项目的策略明确要求在推送到远端协作分支前执行本地审查时，才使用本循环。具体审查工具、审查人、CI 入口、分支和推送命令，一律来自 repo-local 或来源策略的定义，本文件不预设。

## START：进入审查

1. 读取 repo-local 入口或策略文件，确认审查流程的具体参数。
2. 确认即将交付的最终 diff identity、范围、remote target 和当前授权状态。
3. 在开始审查前，先完成 repo contract 要求的本地验证。

## WORK：执行审查

1. 按 repo 策略选择实际的审查面和审查方式。
2. 向审查方提供：最终 diff、目标与范围说明、相关规约文件、已执行验证的结果、已知的明确问题。
3. 对审查发现做分类：阻断项 / 非阻断项 / 误报，每项保留分类依据。
4. 修复阻断项。修复后 diff 发生变化时，重跑受影响的本地验证和审查环节。

## VERIFY：确认可推送

1. 审查针对的是即将交付的最终确切 diff，不是中间版本。
2. 策略要求的全部检查已实际执行。
3. 所有阻断项已解决，或由有权的授权方明确接受。
4. 对远端的写入操作仍处授权范围内。

## END：交付

1. 按策略执行推送或远端更新。
2. 记录实际推送结果。
3. 若无法推送：保留可审查的产物和阻断说明，不伪称已交付。阻塞原因和后续路由写入 closure。

## Review Contract 来源

审查工具、参与者、remote 操作、检查范围、finding severity 和允许的 disposition 全部从当前 repo-local/source policy 获取。该 policy 未定义的动作不能由本 reference 补造。
