# Rollout Plan

## Stage 0 — Clarify
- Goal: define why JARVIS exists and what loop to unlock first.
- Exit criteria:
  - [ ] business intent is explicit
  - [ ] first valuable loop is chosen
  - [ ] initial owners are identified

## Stage 1 — Pilot
- Goal: inventory the minimum sources, repos, and workflows needed for the first loop.
- Exit criteria:
  - [ ] source inventory exists
  - [ ] repo inventory exists
  - [ ] workflow inventory exists
  - [ ] first backlog exists
  - [ ] confirmation checklist is complete or unresolved fields are explicit

## Stage 1.5 — Shadow Pilot
- Goal: run real artifacts while humans retain control.
- Exit criteria:
  - [ ] 3-5 real artifacts or eval cases are selected
  - [ ] at least one START -> WORK -> END run has evidence
  - [ ] failures are classified
  - [ ] skill backlog records no-skill-gap / merge / update / create decisions

## Stage 2 — Operationalize
- Goal: make the pilot loop usable by more than one owner or one agent.
- Exit criteria:
  - [ ] key source / repo / workflow skills are drafted
  - [ ] maintenance rules exist
  - [ ] ownership and handoff are explicit
  - [ ] controlled writeback is reviewed by an owner
  - [ ] calibration cadence exists

## Stage 3 — Scale
- Goal: expand to adjacent loops and reduce rediscovery cost across teams.
- Exit criteria:
  - [ ] adjacent workflows are prioritized
  - [ ] skill coverage expands intentionally
  - [ ] governance and update triggers are working
  - [ ] upstream methodology promotion uses redacted, reusable patterns only
