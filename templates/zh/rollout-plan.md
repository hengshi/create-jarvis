# Rollout 计划

## Stage 0 — Clarify
- Goal: 定义 JARVIS 为什么存在，以及首先要解锁哪条闭环。
- Exit criteria:
  - [ ] business intent 已明确
  - [ ] 第一条有价值闭环已选定
  - [ ] 初始 owners 已识别

## Stage 1 — Pilot
- Goal: 盘点第一条闭环所需的最小 sources、repos 和 workflows。
- Exit criteria:
  - [ ] source inventory 已存在
  - [ ] repo inventory 已存在
  - [ ] workflow inventory 已存在
  - [ ] 第一版 backlog 已存在
  - [ ] confirmation checklist 已完成，或 unresolved fields 已明确

## Stage 1.5 — Shadow Pilot
- Goal: 使用真实 artifacts 运行闭环，同时由 humans 保持控制。
- Exit criteria:
  - [ ] 已选择 3-5 个真实 artifacts 或 eval cases
  - [ ] 至少一条 START -> WORK -> END 有证据
  - [ ] failures 已分类
  - [ ] skill backlog 已记录 no-skill-gap / merge / update / create 决策

## Stage 2 — Operationalize
- Goal: 让 试点 闭环可被不止一个 owner 或一个 agent 使用。
- Exit criteria:
  - [ ] 关键 source / repo / workflow skills 已起草
  - [ ] maintenance rules 已存在
  - [ ] ownership 与 handoff 已明确
  - [ ] controlled writeback 已由 owner review
  - [ ] calibration cadence 已存在

## Stage 3 — Scale
- Goal: 扩展到相邻闭环，并降低团队间的重新发现成本。
- Exit criteria:
  - [ ] 相邻 workflows 已被排定优先级
  - [ ] skill coverage 在有意识地扩展
  - [ ] governance 与 update triggers 正在生效
  - [ ] upstream methodology promotion 只使用脱敏、可复用 patterns
